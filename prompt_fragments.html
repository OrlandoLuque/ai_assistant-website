Prompt Fragments Guide

Composable conditional system prompts — the structural pattern behind Claude Code's ~110 instruction strings, reimagined as an extensible library primitive. Your callers compose; you never fork.

1. What it is (and what it is not)

Prompt fragments are instructions — not data. They tell the model how to behave based on signals you already have at runtime.

Fragments are not RAG. RAG (the rag feature) answers "what data should I put in the context?". Fragments answer "what instructions should I give?". Different primitives, different modules. Do not confuse them.

The leaked Claude Code system prompt contains roughly 110 small conditional strings, each gated on a runtime signal (platform, mode, tool availability, plan mode, attached IDE, …). The value of the pattern is architectural — modular, introspectable, override-friendly — not the specific 110 strings, which are product decisions. We ship the architecture; you ship the content.

2. Why you need it

A static system prompt cannot adapt. Real deployments vary on axes a single string cannot cover without either ballooning the prompt or duplicating it.

  • Platform — Windows shell vs. POSIX.
  • Mode — plan, execute, review, autonomous.
  • Tools available — whether git, retrieve, bash are callable.
  • Region / compliance — EU GDPR reminder, US residency, etc.
  • Domain — research vs. coding vs. general chat.

Without a composition layer you either (a) write one mega-prompt that tries to cover everything — wasting tokens and confusing the model — or (b) maintain N full prompts and branch by hand — duplicating text and drifting between copies. Fragments give you a third option: small units composed at runtime from the signals you already have.

3. Quick start

Enable the feature, pick a preset, add what you need.

1

Enable the feature flag

Cargo.toml 
[dependencies]
ai_assistant = { version = "0.2.23", features = ["prompt-fragments"] }
2

Compose a prompt

Rust 
use ai_assistant::{PromptBuilder, PromptContext, PromptPreset, Platform};

let ctx = PromptContext::default()
    .with_platform(Platform::detect())
    .with_tools(vec!["git".into(), "retrieve".into()])
    .with_locale("en")
    .with_region("EU");

let prompt: String = PromptBuilder::new()
    .with_preset(PromptPreset::CodeDeveloper)
    .add_fragment(ai_assistant::prompt_fragments::catalog::gdpr_eu_notice())
    .build(&ctx);
3

Plug into your assistant

Rust 
use ai_assistant::AiAssistant;

let assistant = AiAssistant::with_system_prompt(&prompt);

6. Writing your own fragments

Custom fragments follow the same shape as the catalog entries.

Rust 
use ai_assistant::{PromptFragment, FragmentCategory, PromptContext};

let frag = PromptFragment::new(
    "company_style_guide",
    "Use British English. Avoid passive voice.",
    FragmentCategory::Style,
    30,
    |ctx: &PromptContext| {
        ctx.custom.get("style")
           .map(|v| v == "british")
           .unwrap_or(false)
    },
);

For unconditional fragments, skip the closure with PromptFragment::always(key, text, category, priority).

7. Priority and ordering

Lower priority appears first. Ties break by insertion order. Suggested ranges so fragments from different sources interleave predictably:

RangeCategory
0–9Safety
10–19ToolGuidance
20–29Context
30–39Style
40–49ModeSpecific
50–59PlatformSpecific
100+Domain / Custom

These are conventions, not enforced. If you deviate, expect the output order to surprise other readers of your code.

8. Introspection

build_with_trace returns the applied fragments in exact output order — useful for debugging and OpenTelemetry spans.

Rust 
let (prompt, trace) = builder.build_with_trace(&ctx);
for applied in &trace {
    eprintln!("{} [{}] prio={}",
        applied.key, applied.category, applied.priority);
}

9. Security — fragment text is trusted

Never build a fragment directly from end-user input. Fragment text is concatenated verbatim into the system prompt. User-controlled text there is a direct prompt-injection vector: a malicious user could supply text that overrides your safety fragments or leaks instructions.

If you need to surface user-facing values (name, preferences) into the prompt, put them in PromptContext.custom and let a trusted fragment read that key explicitly. The fragment's trusted text controls the framing; the untrusted value becomes a parameter, not free-form text.

10. Butler integration (Phase 3 — done)

Butler::recommend_prompt_fragments(intent, &report) returns a seed PromptPreset, a list of overlay fragment keys, and a human-readable justification. Rule-based today; an optional LLM-assisted variant is deferred behind a separate feature flag.

rust

use ai_assistant::butler::Butler;

let mut butler = Butler::new();
let report = butler.scan();
let rec = butler.recommend_prompt_fragments(
    "help me refactor this Rust codebase and add tests",
    &report,
);
println!("{}", rec.justification);
// Use rec.preset as the seed; iterate rec.extra_fragment_keys
// and add the matching catalog entries to your PromptBuilder.

Command-line equivalent:

bash

ai_cli butler recommend-prompt --intent "help me refactor this Rust codebase and add tests"

Keyword dispatch picks the preset (research / code / RAG / autonomous / chat), with a project-type fallback. Extras overlay on top: git_commit_conventions when a VCS is detected, rust_idioms for Rust projects, and the platform shell notes (the fragment self-gates by host OS, so overlaying both windows_shell_note and unix_shell_note is safe).

Example output. “Recommended preset: CodeDeveloper. Reasons: intent mentions coding / development; git repository detected → add git_commit_conventions; Rust project detected → add rust_idioms.”
