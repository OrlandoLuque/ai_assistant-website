Purpose

Runs feature-gated integration test categories without having to remember every cargo test incantation. Used by CI and by local developers to smoke-test a build against the real provider + browser path.

Build

cargo build --release --bin ai_test_harness --features "full,browser"

Categories (selection)

FlagTests covered
--category anti-hallucination3 V88 tests
--category quality-gates4 V88 tests
--category faithfulness2 V88 tests
--category verification2 V88 tests
--category research4 V88 tests (requires research feature)
--category code_gen_benchexecution-verified code-gen pass@1 (11 tasks); backend configurable via AI_BENCH_* env (Ollama / llama.cpp / …)
--category agentic_codea live model drives the built-in AutonomousAgent over write/read/run tools to build & fix code, execution-verified (5 tasks)
--category agentic_multimulti-step agentic coding (build → extend → fix) on one persistent workspace
--category agentic_rustthe same agentic loop in Rust: a throwaway cargo crate per task, verified with cargo test so the type and borrow checkers gate every answer (12 tasks)
--category agentic_rust_multimulti-step Rust on one persistent crate: six additive tasks plus four where a late step invalidates an earlier one — a rename whose callers must be re-pointed, an enum variant that breaks an existing match, an infallible API that becomes fallible (10 tasks)
--category agentic_editthe model is handed an existing crate (several modules plus a passing test suite) and a change request that states the symptom, never the file. Two gates scored apart: the seeded tests must still pass, and the requested change must be there — so “broke something else” and “never made the change” stop arriving as the same failure (8 tasks)
--category agentic_test_geninverted: the model is handed a correct implementation and must write the test suite, scored by mutation — its tests must accept the reference and kill every planted bug (12 tasks)

All seven live-model categories are repeated and scored as a pass rate (AI_BENCH_REPEATS, default 3), with the distribution, a blind-retry projection and the failure modes printed alongside the total. A single run of a live model is one sample of a stochastic process, not a measurement — and runs the backend never completed leave the denominator instead of counting as the model being wrong.

Benchmarks vs regression suite

Seven categories (code_gen_bench, agentic_code, agentic_multi, agentic_rust, agentic_rust_multi, agentic_test_gen, agentic_edit) measure a model, not the code: their pass/fail depends on which model AI_BENCH_MODEL points at. They are therefore excluded from --all, which stays a pure regression gate, and are run deliberately:

ai_test_harness --all           # regression only (609 tests)
ai_test_harness --benchmarks    # only the model-measuring categories
ai_test_harness --list          # marks which is which

Benchmark results are tracked over time in the project's docs/MODEL_BENCHMARKS.md lab notebook rather than as a pass/fail gate.

Benchmark knobs (live-model categories)

Env varEffect
AI_BENCH_PROVIDER / AI_BENCH_MODEL / AI_BENCH_URLwhich backend and model the tasks run against (Ollama, llama.cpp, LM Studio, vLLM…)
AI_BENCH_TEMPsampling temperature (default 0.5). Do not set 0 to chase determinism — the seed is what buys that, and near-greedy sampling can abort the llama.cpp runner outright
AI_BENCH_SEEDsampling seed (default 42, or none to randomise). This is what makes a run reproducible
AI_BENCH_REPEATS=nruns per task (default 3), scored as a pass rate. One live-model run is a single sample of a stochastic process, not a measurement
AI_BENCH_NUM_CTX=ncontext window. Shrinking it is what decides whether a big model fits entirely in VRAM: the KV cache, not the weights, is usually what spills to CPU
AI_BENCH_SCAFFOLD=ngive the agent n verify→feedback→retry rounds, feeding it the real compiler output on failure
AI_BENCH_SAMPLES=nbest-of-N: n independent attempts per task, pass if any succeeds
AGENTIC_DEBUG=1dump each step's model reply and resulting artifact
AGENTIC_TRACE=1fingerprint every prompt and reply, to tell a drifting prompt from a non-reproducible backend
