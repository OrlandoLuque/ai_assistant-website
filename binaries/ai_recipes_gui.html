ai_recipes_guiRecipes auditor (egui desktop)

Group
Workflows (Phase A.1, V106)
Binary path
src/bin/ai_recipes_gui.rs
required-features
gui-recipes (= dep:eframe)

Purpose

Visual read-only auditor for recipes. Pairs with the CLI auditor ai_recipes. Shows: list panel of discovered recipes, metadata grid, per-recipe validation status, sub-recipe call-graph view (with MISSING flagged in red), aggregate summary panel.

Build

cargo build --release --bin ai_recipes_gui --features gui-recipes

Run

cargo run --release --bin ai_recipes_gui --features gui-recipes

Default directory: ./.ai_assistant/recipes. Change in the toolbar and click Reload.

Why a separate gui-recipes feature?

The auditor only needs eframe — it does not pull in the rest of the desktop stack (graph viz, file dialogs, RAG, butler) that gui-pro brings. Users who want only the recipes auditor pay only for that.
