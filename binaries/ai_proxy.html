Drop ai_proxy in front of one or more upstream LLM backends (Ollama, LM Studio, OpenAI, Anthropic, …) and every client keeps talking plain OpenAI‑compatible HTTP — while the proxy adds load balancing, safety guardrails, cost control, caching, and an audit trail. It is the same binary at two strengths: a thin router, or a fully hardened gateway.

What it can do

  • Multi-backend load balancing across upstreams with round-robin and session affinity (sticky routing per session).
  • Model-aware routing (V149): send each request to a backend that actually advertises the requested model; aggregated GET /v1/models shows the whole fleet.
  • Health checks that take unhealthy backends out of rotation automatically.
  • Bearer auth gate (optional) with the key compared safely and never logged in clear.
  • Rate limiting per key (sliding window, keyed sha256(bearer) → session → ip).
  • Guardrails: PII redaction (input + output), toxicity filtering, and prompt-injection / attack detection.
  • Budget enforcement: returns 429 with X-Reason: budget-exceeded when a key blows its cost ceiling.
  • Response cache (LRU, PII-safe — tainted responses are never stored).
  • Append-only JSONL audit log with rotation, symlink-safe open, and API keys stored only as SHA-256 hashes.
  • SSE streaming passthrough (V150) with a per-chunk inactivity timeout (anti slow-loris) and Prometheus /metrics.
  • Request dedupe + multi-hop loop guard (V149) via x-request-id / x-forward-hops.

What it can’t do (by design / yet)

  • It is not a model server. It forwards to your backends — it never runs inference itself.
  • Output guardrails don’t run over a live stream. When stream: true is honoured, the body is passed through; if guards are active the response is buffered instead and the proxy sets x-streaming-disabled: output-guard-active so you can tell.
  • Streams are not cached (the cache layer is bypassed for streaming requests).
  • No built-in TLS termination. Put it behind a reverse proxy / load balancer for HTTPS, or use the dedicated TLS-capable servers.
  • The security guardrails are opt-in — the router profile (without security) does load balancing only.

Build

# Router only (LB + health + optional auth)
cargo build --release --bin ai_proxy --features server-axum

# Hardened gateway (recommended for anything public)
cargo build --release --bin ai_proxy --features "server-axum,security"

Tutorial: a hardened gateway in 5 steps

  1. Start two backends (e.g. two Ollama instances on 127.0.0.1:11434 and 11435).
  2. Copy the example config and edit the backend list: 
    cp examples/ai_proxy.toml ai_proxy.toml
# edit [[backends]] addr = "127.0.0.1:11434" / ":11435"
  3. Set an API key via env (wins over the file and the deprecated flag): 
    export AI_PROXY_API_KEY="sk-your-gateway-key"
  4. Dry-run to validate the merged config before binding a port: 
    ai_proxy --config ai_proxy.toml --dry-run
  5. Run it and point any OpenAI client at it: 
    ai_proxy --config ai_proxy.toml --port 9000

curl http://localhost:9000/v1/chat/completions \
  -H "Authorization: Bearer sk-your-gateway-key" \
  -H "Content-Type: application/json" \
  -d '{"model":"llama3","messages":[{"role":"user","content":"hi"}]}'

Watch X-Request-Id, X-Cache, and the audit log fill in as you send traffic. Hit /metrics for Prometheus counters and /v1/models for the aggregated fleet.

Common use cases

  • One safe endpoint for a team — a single Bearer-gated URL in front of several local models, with per-key rate limits and budgets so nobody runs away with the GPU.
  • PII firewall — force PII redaction on input and output so prompts/responses are scrubbed before they reach (or leave) the model.
  • Cost guardrail for a shared model — set a budget per key; the gateway 429s once it’s exhausted, with an auditable trail of who spent what.
  • Model fleet behind one address — model-aware routing + aggregated /v1/models let clients ask for any model and land on a backend that serves it.
  • Drop-in cache — identical chat requests are served from an LRU cache (PII-safe), cutting load on the backends.

Configuration reference

ai_proxy --config ai_proxy.toml             # TOML config (recommended)
ai_proxy --config ai_proxy.toml --dry-run   # validate + print merged config, exit
ai_proxy --config ai_proxy.toml --port 9000 --disable-cache

CLI flags (all optional, all override the file): --config, --port, --backends a:p,b:p, --health-interval, --audit-log, --audit-max-files, --enable-pii-redaction, --disable-cache, --cost-snapshot, --dry-run, --api-key (deprecated — prefer the env var).

Environment: AI_PROXY_API_KEY — Bearer key; wins over both the config file and --api-key.

Response headers: X-Request-Id (every response), X-Cache: HIT|MISS (chat path), X-Reason on 429/503 (budget-exceeded, rate_limit, output-blocked, middleware-error).

Middleware pipeline (security on)

rate limit → content-length guard → PII input → toxicity input → attack guard → budget pre-check → cache lookup → backend → PII output → toxicity output → budget post-update → cache store → audit log.
