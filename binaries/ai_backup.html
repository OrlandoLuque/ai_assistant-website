ai_backupEncrypted, signed archive tool

Group
Setup & Ops (V128)
Binary path
src/bin/ai_backup.rs
required-features
backup

Purpose

Create an AES-256-GCM-encrypted, optionally Ed25519-signed, content-addressable archive of one or more source paths — then verify or restore it. Backs the backup::{create,verify,restore}_backup library API. Opt-in so users who only need providers don't pull crypto deps.

Build

cargo build --release --bin ai_backup --features backup

Usage

ai_backup create  --source <path> [--source <path>]... --output <base> \
                  [--passphrase-env VAR] [--sign-key <path>] [--label <text>]
ai_backup verify  --input <archive> [--passphrase-env VAR] [--verify-key <path>]
ai_backup restore --input <archive> --output <dir> [--passphrase-env VAR] [--verify-key <path>]

Defenses

  • The CLI never reads passphrases from argv — --passphrase-env names an environment variable instead.
  • --sign-key / --verify-key are 32-byte raw Ed25519 keys on disk.
  • Without a passphrase the archive is plain but still SHA-256-summed; a .sha256 sidecar is always written, a .sig when a signing key is supplied.
  • AES-256-GCM provides authenticated encryption: tampering with the ciphertext fails decryption atomically.
  • Verify before restore: verify checks the SHA-256 and (when present) the Ed25519 signature without unpacking anything.
