Authentication

When auth.enabled = true, all requests (except exempt paths) must include one of:

MethodHeaderExample
Bearer TokenAuthorizationAuthorization: Bearer my-secret
API KeyX-API-KeyX-API-Key: abc123

Exempt paths (default): /health

Failure response: 401

JSON 
{
  "error": "Authentication required"
}
Security: Token comparison uses constant-time XOR to prevent timing side-channel attacks. Auth is disabled by default for development — always enable it in production.

Error Format

All errors return a structured JSON body:

JSON 
{
  "error_code": "INVALID_JSON",
  "message": "Failed to parse request body",
  "details": "expected ',' or '}' at line 3 column 1",
  "retry_after_secs": null
}
CodeHTTP StatusDescription
INVALID_JSON400Malformed JSON in request body
AUTH_FAILED401Missing or invalid authentication
RATE_LIMITED429Too many requests; check Retry-After
VALIDATION_ERROR422Request validation failed (message too long, etc.)
MODEL_ERROR500LLM provider returned an error
INTERNAL_ERROR500Unexpected server error
NOT_FOUND404Unknown endpoint

Internal Error Taxonomy (error_taxonomy::ErrorCode)

The HTTP error_code above is the wire-level taxonomy. Internally, every Rust error type that crosses a public boundary implements the ErrorCode trait, exposing a stable fine-grained code (e.g. PROVIDER_RATE_LIMITED, ANTHROPIC_API, RESILIENT_ALL_PROVIDERS_FAILED), structured fields as (&'static str, String) pairs (e.g. ("status_code", "429"), ("retry_after_ms", "2000")), and an optional category. Localized templates live in errors/en.json and errors/es.json (83 codes each at V116) with {field} placeholders substituted at format time.

StructuredError::from_err collapses any ErrorCode implementor into a serializable { code, fields, category? } shape — the same shape consumed by JSON logs, the i18n resolver, and OTel span attributes (error.code, error.fields.*). At V116, 16 types implement the trait: the AiError umbrella + 8 sub-types (ConfigError, ProviderError, RagError, NetworkError, ValidationError, ResourceLimitError, IoError, SerializationError), the RAG / embeddings subsystem types (RagPipelineError, EmbeddingError, KpkgError), and the provider-call adapters (AnthropicAdapterError, OpenAIAdapterError, HfError, ResilientError). The migration is additive — the inherent code() method on AiError still returns the coarse string ("PROVIDER", "CONFIG", …) for API compatibility; the fine-grained code is reachable via <AiError as ErrorCode>::code(&err).

Ollama-Compatible Endpoints

These three endpoints speak Ollama’s wire dialect, so a tool that believes it is talking to a local Ollama daemon can be pointed at this server and work without knowing anything about it. Many tools hardcode localhost:11434 and these exact paths.

Served at the literal path only. Unlike every other endpoint, these have no /api/v1/ alias. That is deliberate: the tools these routes exist for look for the exact path Ollama uses, so a prefixed alias would be of no use to them.
The answer is not incremental. All three respond with a single NDJSON line carrying done: true. That is exactly right for stream: false (one JSON object), and it is a valid one-element stream for the stream: true Ollama defaults to — but the whole answer arrives at once. A client that paints tokens as they land will work, and will paint them all in one frame.
model is accepted and ignored. The server answers with the model it is configured with, and reports that model in the response. It does not switch models per request.
GET /api/tags

List the available models in Ollama’s format.

Response 200 OK

JSON 
{
  "models": [
    {
      "name": "llama3:latest",
      "model": "llama3:latest",
      "modified_at": "2026-09-05T12:00:00Z",
      "size": 4661211808,
      "digest": "",
      "details": {"family": "llama", "parameter_size": "8B", "quantization_level": "Q4_K_M"}
    }
  ]
}

size is an integer byte count, as Ollama specifies. The library’s internal ModelInfo::size is a display string ("7.0 GB"); it is converted here, and when the string cannot be parsed the field is omitted rather than guessed. Emitting 0 would have told the client the model is empty — a confident, wrong answer where silence is the correct one.

Request Body

JSON 
{
  "model": "llama3",
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "What is Rust?"}
  ],
  "stream": false
}
FieldTypeRequiredDescription
modelstringNoAccepted and ignored (see above)
messagesarrayYes{role, content} objects; at least one user turn
streambooleanNoAccepted; the response shape is the same either way

Errors

  • 422 A message exceeds the configured maximum length
  • 504 Generation timed out

Single-prompt completion. Same response shape and same caveats as /api/chat, with the text in response rather than message.content.

Request Body

  "model": "llama3",
  "prompt": "What is Rust?",
  "system": "You are a helpful assistant.",
  "stream": false
}

Response 200 OK application/x-ndjson

JSON 
{"model":"llama3","created_at":"2026-09-05T12:00:00Z","response":"Rust is...","done":true,"done_reason":"stop"}

Errors

  • 400 Body could not be parsed, or prompt is missing
  • 422 The prompt exceeds the configured maximum length
  • 504 Generation timed out

WebSocket

WS /ws

WebSocket chat endpoint (RFC 6455). Supports persistent bidirectional connections for real-time chat.

Upgrade Request

HTTP 
GET /ws HTTP/1.1
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13

Client → Server Message

JSON 
{
  "message": "Hello, assistant!",
  "system_prompt": "You are a helpful assistant"
}

Server → Client Frames

JSON 
{"type": "chunk", "data": "Hello"}
{"type": "chunk", "data": "! How"}
{"type": "chunk", "data": " can I help?"}
{"type": "done"}

JavaScript Example

JavaScript 
const ws = new WebSocket('ws://localhost:8090/ws');

ws.onopen = () => {
  ws.send(JSON.stringify({ message: 'Hello!' }));
};

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.type === 'done') return;
  document.getElementById('output').textContent += msg.data;
};
Origin validation: WebSocket upgrade requests are validated against the configured allowed_origins. Connections from unauthorized origins are rejected before the upgrade completes.

Enrichment Pipeline

When enrichment is enabled via ServerConfig.enrichment, both native and OpenAI-compatible endpoints apply a full processing pipeline:

Request → Cost Check → Input Guard → RAG Context → LLM → Output Guard → Response

Top-Level Configuration

FieldTypeDefaultDescription
enable_ragboolfalseEnable RAG context retrieval
enable_guardrailsboolfalseEnable input guardrails
enable_memoryboolfalseEnable conversation memory
block_on_input_violationbooltrueReturn 400 on guardrail violations
redact_output_piibooltrueMask PII in responses
guardrail_thresholdf320.8Guardrail confidence threshold

The enrichment config has 52 configurable fields across 7 sub-configs: guardrails (18), rag (8), context (5), compaction (6), model_selection (5), cost (5), thinking (7).

Rate Limiting

The server tracks requests per time window (global + per-IP). Exceeding the limit returns:

429 Too Many Requests 
{
  "error_code": "RATE_LIMITED",
  "message": "Rate limit exceeded",
  "retry_after_secs": 30
}

The Retry-After header indicates seconds to wait before retrying. Per-IP limits are automatically calculated as global_rpm / 4 (minimum 10).

CORS

The server handles CORS preflight (OPTIONS) requests automatically based on CorsConfig.

bash 
# Preflight request
curl -X OPTIONS \
  -H "Origin: https://app.example.com" \
  -H "Access-Control-Request-Method: POST" \
  http://localhost:8090/chat

# Response headers:
# Access-Control-Allow-Origin: *
# Access-Control-Allow-Methods: GET, POST, OPTIONS
# Access-Control-Allow-Headers: Content-Type, Authorization, X-API-Key
# Access-Control-Max-Age: 86400
Security: Wildcard origin (*) with Access-Control-Allow-Credentials is automatically blocked. Use specific origins in production.

Python 
import requests

BASE = "http://localhost:8090/api/v1"
HEADERS = {"Authorization": "Bearer my-token"}

# Simple chat
resp = requests.post(f"{BASE}/chat",
    json={"message": "Hello!"},
    headers=HEADERS)
print(resp.json()["content"])

# Streaming chat (SSE)
resp = requests.post(f"{BASE}/chat/stream",
    json={"message": "Tell me a story"},
    headers=HEADERS,
    stream=True)
for line in resp.iter_lines():
    if line:
        text = line.decode()
        if text.startswith("data: ") and text != "data: [DONE]":
            import json
            token = json.loads(text[6:])["token"]
            print(token, end="", flush=True)

# OpenAI-compatible (works with openai library)
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8090/v1", api_key="my-token")
response = client.chat.completions.create(
    model="llama3.2",
    messages=[{"role": "user", "content": "What is Rust?"}]
)
print(response.choices[0].message.content)
JavaScript 
const BASE = 'http://localhost:8090/api/v1';
const HEADERS = {
  'Content-Type': 'application/json',
  'Authorization': 'Bearer my-token'
};

// Simple chat
const resp = await fetch(`${BASE}/chat`, {
  method: 'POST',
  headers: HEADERS,
  body: JSON.stringify({ message: 'Hello!' })
});
const data = await resp.json();
console.log(data.content);

// SSE Streaming
const streamResp = await fetch(`${BASE}/chat/stream`, {
  method: 'POST',
  headers: HEADERS,
  body: JSON.stringify({ message: 'Tell me a story' })
});
const reader = streamResp.body.getReader();
const decoder = new TextDecoder();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  const text = decoder.decode(value);
  for (const line of text.split('\n')) {
    if (line.startsWith('data: ') && line !== 'data: [DONE]') {
      const { token } = JSON.parse(line.slice(6));
      process.stdout.write(token);
    }
  }
}

// WebSocket
const ws = new WebSocket('ws://localhost:8090/ws');
ws.onopen = () => ws.send(JSON.stringify({ message: 'Hello!' }));
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type !== 'done') console.log(msg.data);
};
