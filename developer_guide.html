Architecture Overview

Key design principles:

  • Single crate, feature-gated — No workspace, no sub-crates. Feature flags control what compiles.
  • Zero .unwrap() in production code — all errors propagated via Result
  • Zero clippy warnings — clean builds across all feature combinations
  • Sync-first API — AiAssistant owns a tokio::runtime::Runtime internally; callers use synchronous polling
  • No external state — Everything can run embedded, no mandatory external services

Knowledge Packages (.kpkg)

Encrypted knowledge packages bundle multiple documents with AES-256-GCM encryption. Distribute domain knowledge securely:

Rust 
use ai_assistant::{KpkgWriter, KpkgReader};

// Create an encrypted package
let mut writer = KpkgWriter::new("my-secret-key");
writer.add_document("guide.md", &content);
writer.add_document("faq.txt", &faq_content);
let package_bytes = writer.finish()?;

// Read and decrypt
let reader = KpkgReader::new("my-secret-key");
let docs = reader.read(&package_bytes)?;
for doc in &docs {
    println!("{}: {} bytes", doc.name, doc.content.len());
}

Composable Prompt Fragments (v0.2.23)

The prompt-fragments feature replaces hand-written monolithic system prompts with PromptFragments — small, named, priority-ordered chunks composed by PromptBuilder. Each fragment carries a FragmentCategory (Safety, ToolGuidance, Context, Style, ModeSpecific, PlatformSpecific, Custom) and optional Platform gating (ClaudeCode, Gui, Server, Any). The builder filters by PromptContext, sorts by priority, and returns the final prompt plus an AppliedFragments manifest showing exactly what went in.

Ships 11 catalog fragments and 6 presets: Minimal, ToolUseChatbot, RagAssistant, AgenticLoop, ResearchAgent, CodeDeveloper. Priority ranges are conventionalised: 0-9 Safety, 10-19 ToolGuidance, 20-29 Context, 30-39 Style, 40-49 ModeSpecific, 50-59 PlatformSpecific, 100+ Custom. Butler::recommend_prompt_fragments() maps keyword intents ("search papers", "write code") to a suggested preset + extras.

rust 
use ai_assistant::{
    PromptBuilder, PromptContext, PromptPreset, Platform,
};

let ctx = PromptContext::new()
    .with_platform(Platform::Server)
    .with_has_tools(true);

let (prompt, applied) = PromptBuilder::from_preset(PromptPreset::AgenticLoop)
    .with_context(ctx)
    .with_custom_fragment("project", "You are working on the ai_assistant crate.", 100)
    .build();

// prompt: final system prompt string
// applied: AppliedFragments { fragments: [...], total_priority_ordered: [...] }

StallHeuristic robustness — Overheating, multi-language, LLM-assisted (v0.2.27)

V95 adds three extensions to the V93 StallHeuristic, all additive: an Overheating signal (rate-based), per-language frustration lexicons (Spanish / French / German), and a LlmAssistedStallDetector wrapper behind the optional stall-detection-llm feature.

Signal precedence in check(): RepeatedToolCall (definite loop) > Overheating (real-time rate) > Frustrated (lagging user signal).

rust 
use std::time::Duration;
use ai_assistant::{
    KeywordStallDetector, RateThresholds, StallDecision,
    StallHeuristic, StallLanguage, StallSignal,
};

let mut det = KeywordStallDetector::new()
    .with_language(StallLanguage::Spanish)
    .with_rate_thresholds(RateThresholds::new(Duration::from_secs(60), 20));

det.observe_user_message("Esto no funciona, estoy harto");
assert_eq!(det.check(), StallDecision::Stalled(StallSignal::Frustrated));
rust 
// stall-detection-llm: plug a caller-provided LLM into the loop.
use std::sync::Arc;
use std::time::Duration;
use ai_assistant::{
    KeywordStallDetector, LlmAssistedStallDetector, LlmVerdict,
    LlmVerdictFn, LlmVerdictInput, StallHeuristic, StallSignal,
};

let verdict_fn: LlmVerdictFn = Arc::new(|input: &LlmVerdictInput| {
    // Caller wires this into their own LLM stack (Anthropic, Ollama, etc.)
    if input.last_user_message.contains("stuck") {
        LlmVerdict::Stalled(StallSignal::Frustrated)
    } else {
        LlmVerdict::Continue
    }
});

let inner = KeywordStallDetector::new();
let mut wrapper = LlmAssistedStallDetector::new(inner, verdict_fn)
    .with_min_interval(Duration::from_secs(30)); // cooldown

wrapper.observe_user_message("I'm stuck on step 3");
// inner says Continue; LLM overrides to Stalled(Frustrated).

AgenticLoop auto-integration. Attach any StallHeuristic to an AgenticLoop and the loop forwards user messages and tool calls automatically; a Stalled verdict flips status to UserStalled and breaks.

rust 
use ai_assistant::{
    AgenticLoop, KeywordStallDetector, LoopConfig, LoopStatus,
};

let mut agent = AgenticLoop::new(LoopConfig::default())
    .with_stall_heuristic(Box::new(KeywordStallDetector::new()));

let result = agent.process("ugh, this is useless, forget it");
assert_eq!(result.status, LoopStatus::UserStalled);
// agent.stall_heuristic() / stall_heuristic_mut() expose the attached detector.

Ephemeral sub-agent spawning (v0.2.26)

The sub-agents feature adds a structural equivalent of Claude Code’s Task tool: Fork / Teammate / Explore. The main agent produces a SubAgentSpec, a SubAgentRunner executes it, and a single SubAgentResult comes back. Orthogonal to the persistent AgentOrchestrator — sub-agents are fire-and-forget.

True filesystem or process isolation (git worktree, subprocess, remote worker) stays a caller concern. The crate ships the declarative model, a pluggable trait, and a default InProcessSubAgentRunner. Specs with IsolationLevel::ExternalProcess return SubAgentStatus::Deferred so callers can route them to their own runner without ambiguity.

rust 
use ai_assistant::{
    AgentRole, InProcessSubAgentRunner, IsolationLevel,
    SubAgentKind, SubAgentRunner, SubAgentSpec, SubAgentStatus,
};

let runner = InProcessSubAgentRunner::new();

let spec = SubAgentSpec::new("review-1", SubAgentKind::Teammate, "review the draft")
    .with_role(AgentRole::PeerReviewer)
    .with_context_summary("3-paragraph draft on quantum computing")
    .with_isolation(IsolationLevel::ContextIsolated)
    .with_budget_hint(4_000);

let result = runner.run(&spec);
assert_eq!(result.status, SubAgentStatus::Completed);
assert_eq!(result.spec_id, "review-1");

Agent Methodology

AgentMethodology defines how an agent approaches tasks — separate from what tools it has. It controls the task approach (PlanFirst / ActFirst / Iterative), reasoning strategy (ChainOfThought / StepBack / Reflection / Direct), planning policy, review policy, recovery strategy, communication style, and risk tolerance.

The WorkflowProtocol defines 6 phases — ANALYZE → PLAN → VALIDATE → EXECUTE → REVIEW → CONCLUDE — each with PhaseConfig { enabled, mandatory, max_duration_secs }. ReviewTriggers define 8 conditions that force a review cycle (iteration count, milestone, tool failure, cost threshold, time threshold, user interrupt, periodic self-check). QualityGate checks gate progress between phases (OutputNotEmpty, CostWithinBudget, LlmJudge, etc.).

Sandbox Validator (Runtime Enforcement)

SandboxValidator sits between the agent and every action, validating against the AgentPolicy and maintaining a complete audit trail. Every tool call, file access, and network request passes through the sandbox before execution.

Risk levels: Safe < Low < Medium < High < Critical. Actions above the configured threshold require user approval. All decisions are logged with AuditEntry (timestamp, action, decision, risk level).

Browser Policy

BrowserPolicy controls browser automation security: URL validation (SSRF protection, domain allowlist/blocklist, private IP blocking), JavaScript permission levels (Disabled / ReadOnly / Mutating / Full), and interaction controls (cookies, forms, downloads). 16 dangerous JS patterns are detected and blocked based on the permission level.

Building an Agent (Full Example)

rust 
// Layer 1: Policy — WHAT it can do
let policy = AgentPolicyBuilder::new()
    .autonomy(AutonomyLevel::Normal)
    .internet(InternetMode::SearchOnly)
    .allow_path("/data")
    .max_cost(5.0)
    .build();

// Layer 2: Methodology — HOW it works
let methodology = AgentMethodology::careful();

// Layer 3: Build runtime agent
let agent = AutonomousAgent::builder("auditor", response_gen)
    .system_prompt("You are a security auditor...")
    .policy(policy)
    .methodology(methodology)
    .max_iterations(100)
    .tool_registry(tools)
    .with_knowledge_provider(rag_provider)
    .with_interaction_manager(interaction)
    .build();

// Run
let result = agent.run("Analyze the codebase for vulnerabilities")?;

Multi-Agent Orchestration

MultiAgentSession orchestrates multiple agents working on a shared task. Each agent has its own policy and methodology. They share a TaskBoard for coordination and an InteractionManager for user communication.

rust 
let mut session = MultiAgentSession::new("code-review");

// Agent 1: Careful reviewer
let reviewer = AutonomousAgent::builder("reviewer", gen.clone())
    .policy(AgentPolicy::default())
    .methodology(AgentMethodology::research())
    .build();

// Agent 2: Fast fixer
let fixer = AutonomousAgent::builder("fixer", gen.clone())
    .policy(AgentPolicy::autonomous())
    .methodology(AgentMethodology::fast())
    .build();

session.add_agent("reviewer", reviewer);
session.add_agent("fixer", fixer);

Security Model

Security is built into every layer, not bolted on. The crate has been through a comprehensive security audit (300+ attack vectors catalogued and mitigated across multi-pass exhaustive audits).

RBAC Access Control

Role-based access with granular conditions: time ranges, IP ranges, max usage limits, MFA requirements. CIDR notation support.

Constitutional Guardrails

Pre-send and post-receive guardrails. Attack detection (prompt injection, jailbreak), toxicity filtering, content moderation.

PII Detection

Detects and redacts: SSN, credit cards, emails, phone numbers, IP addresses. Configurable sensitivity levels.

Encryption

AES-256-GCM for knowledge packages. SecureString with volatile zeroization. Constant-time comparisons.

SSRF Protection

Blocks requests to private IP ranges (127.x, 10.x, 172.16-31.x, 192.168.x, 169.254.x). MCP tool argument scanning.

Command Injection

Shell metacharacter rejection. No sh -c. Commands split into program + args. Docker exec hardened.

Path Traversal

Canonicalization + .. rejection in shared folders, agent policies, and file operations.

API Security

Constant-time token comparison, per-IP rate limiting, CORS validation, WebSocket origin checks, CRLF sanitization.

Audit results: 5 Critical + 12 High + 14 Medium findings — all resolved. Zero unsafe except volatile zeroization. Zero hardcoded secrets across 500 files.

MCP Protocol

ai_assistant implements the Model Context Protocol v2 (2025-03-26) specification. The MCP server exposes 40+ tools, resources, and prompts that LLM clients can discover and invoke.

Key capabilities:

Error Handling

The crate uses a comprehensive error type hierarchy with no panics in production code. The top-level AiError enum covers all failure modes:

Rust 
pub enum AiError {
    // Core errors

API Stability

ai_assistant marks 454 enums and 246 structs with #[non_exhaustive], ensuring that the public API can evolve without semver-breaking changes. This section explains the practical implications for downstream code.

Matching Non-Exhaustive Enums

Every match on a library enum must include a wildcard arm. The compiler enforces this for types annotated with #[non_exhaustive], so your code won't break when a future minor release adds new variants.

Rust 
use ai_assistant::AiError;

match error {
    AiError::ProviderError(msg) => log::error!("provider: {msg}"),
    AiError::ConfigError(msg)   => log::error!("config: {msg}"),
    AiError::NetworkError(msg)  => log::error!("network: {msg}"),
    // Required: wildcard arm catches current + future variants
    other => log::warn!("other error: {other}"),
}

Constructing Non-Exhaustive Structs

Struct literal syntax (MyStruct { field: value }) is disallowed for non-exhaustive types. Use Default + field assignment, or the provided constructor.

Rust 
use ai_assistant::AssistantConfig;

// Option A: Default + field assignment
let mut config = AssistantConfig::default();
config.provider = "ollama".into();
config.model = "llama3".into();

// Option B: builder / constructor (where available)
let config = AssistantConfig::new("ollama", "llama3");
Do not use struct literal syntax for library types. It will fail to compile because #[non_exhaustive] prevents external crates from listing all fields.

Trait Stability Guarantees

When the library adds new methods to public traits, they always ship with a default implementation. This means existing trait implementors continue to compile without changes. You can override the new methods when you are ready, but you are never forced to.

Rust 
// Library defines (existing trait, new method added in v0.39):
pub trait LlmProvider {
    fn chat(&self, messages: &[Message]) -> Result<Response, AiError>;

    // New in v0.39 — default impl keeps existing impls compiling
    fn supports_streaming(&self) -> bool { false }
}
Summary: Use wildcard match arms for enums, Default or constructors for structs, and rely on default method implementations when implementing library traits. These conventions let you upgrade minor versions without code changes.

V50 — Distributed MapReduce

V50 transforms MapReduce from local-only execution to actual distributed computation across network nodes.

The Challenge

Rust closures capture local state and cannot be serialized across the network. The solution is MapWorkerRegistry: each participating node registers the same map/reduce functions under a shared job_id. When a MapTask arrives, the receiving node looks up the function by ID and executes it locally.

New Capabilities

  • MapWorkerRegistry: register/lookup map and reduce functions by job_id across nodes
  • execute_distributed_with_results(): splits chunks between local node (rayon) and remote peers, merges results, runs shuffle + reduce
  • Self as worker: the coordinator always processes its share locally, even when remote peers are available
  • Graceful fallback: if no remote peers are available, all chunks are processed locally (identical to pre-V50 behavior)
  • Round-robin allocation: chunks are distributed evenly across all available workers
