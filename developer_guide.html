Architecture Overview

Key design principles:

  • Single crate, feature-gated — No workspace, no sub-crates. Feature flags control what compiles.
  • Zero .unwrap() in production code — all errors propagated via Result
  • Zero clippy warnings — clean builds across all feature combinations
  • Sync-first API — AiAssistant owns a tokio::runtime::Runtime internally; callers use synchronous polling
  • No external state — Everything can run embedded, no mandatory external services

Provider Failover

The auto_model_selection module provides intelligent routing with failover:

  • Bandit algorithms — Epsilon-greedy and UCB for model selection based on response quality
  • NFA/DFA routing — State-machine-based provider selection with configurable rules
  • Composite rewards — Multi-objective optimization (quality, latency, cost)
  • Automatic failover — If a provider is down, traffic routes to the next available one
Rust 
use ai_assistant::{AiAssistant, ProviderType};

let mut assistant = AiAssistant::new();

// Configure multiple providers
assistant.set_provider(ProviderType::Ollama);
assistant.set_provider_url("http://localhost:11434");

// Switch at runtime
assistant.set_provider(ProviderType::OpenAi);
assistant.set_api_key("sk-...");

// Auto-selection based on query complexity
// (requires auto_model_selection module)
let response = assistant.generate_with_auto_selection("Complex analysis query...");

Knowledge Packages (.kpkg)

Encrypted knowledge packages bundle multiple documents with AES-256-GCM encryption. Distribute domain knowledge securely:

Rust 
use ai_assistant::{KpkgWriter, KpkgReader};

// Create an encrypted package
let mut writer = KpkgWriter::new("my-secret-key");
writer.add_document("guide.md", &content);
writer.add_document("faq.txt", &faq_content);
let package_bytes = writer.finish()?;

// Read and decrypt
let reader = KpkgReader::new("my-secret-key");
let docs = reader.read(&package_bytes)?;
for doc in &docs {
    println!("{}: {} bytes", doc.name, doc.content.len());
}

Security Model

Security is built into every layer, not bolted on. The crate has been through a comprehensive security audit (31 findings, all resolved).

RBAC Access Control

Role-based access with granular conditions: time ranges, IP ranges, max usage limits, MFA requirements. CIDR notation support.

Constitutional Guardrails

Pre-send and post-receive guardrails. Attack detection (prompt injection, jailbreak), toxicity filtering, content moderation.

PII Detection

Detects and redacts: SSN, credit cards, emails, phone numbers, IP addresses. Configurable sensitivity levels.

Encryption

AES-256-GCM for knowledge packages. SecureString with volatile zeroization. Constant-time comparisons.

SSRF Protection

Blocks requests to private IP ranges (127.x, 10.x, 172.16-31.x, 192.168.x, 169.254.x). MCP tool argument scanning.

Command Injection

Shell metacharacter rejection. No sh -c. Commands split into program + args. Docker exec hardened.

Path Traversal

Canonicalization + .. rejection in shared folders, agent policies, and file operations.

API Security

Constant-time token comparison, per-IP rate limiting, CORS validation, WebSocket origin checks, CRLF sanitization.

Audit results: 5 Critical + 12 High + 14 Medium findings — all resolved. Zero unsafe except volatile zeroization. Zero hardcoded secrets across 313 files.

pub enum StreamEvent {
    Chunk(String),           // A token/fragment
    Complete(String),        // Full response assembled
    Error(String),           // Error during generation
    ThinkingStart,           // Model started reasoning

MCP Protocol

ai_assistant implements the Model Context Protocol v2 (2025-03-26) specification. The MCP server exposes 40+ tools, resources, and prompts that LLM clients can discover and invoke.

Key capabilities:

  • Tools — LLM integration, document processing, web search, code execution, knowledge graph queries
  • Resources — Configuration, session data, metrics exposed as MCP resources
  • Prompts — Pre-built prompt templates for common tasks
  • Sampling — Server-initiated LLM calls through the client
  • OAuth — PKCE (SHA-256) authentication flow for secure connections
  • Transport — Streamable HTTP (replacing SSE), stdio for local processes
See the MCP Tool Catalog for the full list of tools with parameters and usage examples.

Distributed Computing

Two levels of distributed support:

  • distributed (in full) — CRDTs, DHT Kademlia, MapReduce. Data structures and algorithms for distributed coordination.
  • distributed-network (opt-in) — QUIC/TLS 1.3 networking. Real peer-to-peer connections with peer discovery, anti-entropy sync, Merkle trees, and reputation tracking.

Network Features

QUIC + TLS 1.3

Encrypted transport via quinn/rustls. Mutual TLS with Ed25519 certificates.

Peer Discovery

LAN broadcast, seed nodes, peer exchange, NAT traversal (STUN, UPnP, NAT-PMP, ICE).

Anti-Entropy Sync

Merkle tree-based delta sync. Efficient state reconciliation between nodes.

Security

Join tokens with expiration/usage limits. HMAC-SHA256 challenge-response. Reputation & probation.

Configuration System

Configuration supports TOML and JSON formats with hot-reload capability. Runtime changes to model, temperature, and log level take effect without restart.

config.toml

type = "ollama"           # Provider: ollama, lm_studio, openai, anthropic, ...

[urls]

lm_studio = "http://localhost:1234"

[generation]
temperature = 0.7         # 0.0 (deterministic) to 2.0 (creative)
max_history = 20          # Conversation messages to keep
system_prompt = "You are a helpful assistant."

[rag]
enabled = true
knowledge_tokens = 2000   # Max tokens for RAG context
conversation_tokens = 1500

[server]
host = "127.0.0.1"        # Bind address (127.0.0.1 = local only)
port = 8090
max_body_size = 1048576   # 1MB request body limit
trust_proxy = false       # Trust X-Forwarded-For headers

[server.auth]

[server.cors]

allow_credentials = false

[server.rate_limit]

Programmatic Configuration

Rust 
use ai_assistant::{AiAssistant, AiConfig};

// Load from file
let config = AiConfig::from_file("config.toml")?;
let mut assistant = AiAssistant::from_config(config);

// Or configure programmatically
let mut assistant = AiAssistant::new();
assistant.set_temperature(0.7);
assistant.set_max_history(20);
assistant.set_system_prompt("You are a helpful coding assistant.");

Hot Reload

The ConfigWatcher monitors config files and applies changes at runtime. Only safe fields are hot-reloadable (model, temperature, log level). Structural changes (like enabling new features) require a restart.

Error Handling

The crate uses a comprehensive error type hierarchy with no panics in production code. The top-level AiError enum covers all failure modes:

Rust 
pub enum AiError {
    // Core errors
    ProviderError(String),      // LLM provider failures
    ConfigError(String),        // Configuration problems
    NetworkError(String),       // HTTP/network issues
    ParseError(String),         // JSON/response parsing
    IoError(std::io::Error),    // File system operations

    // Feature-specific errors
    RagError(String),           // RAG pipeline failures
    SecurityError(String),      // Auth, RBAC, guardrail violations
    McpError(String),           // MCP protocol errors
    AgentError(String),         // Multi-agent coordination
    StreamingError(String),     // SSE/WebSocket issues
    // ... and more per feature
}

// Contextual errors with ResultExt trait
use ai_assistant::ResultExt;

let data = std::fs::read("file.txt")
    .context("reading knowledge file")?;  // Adds context to io::Error
Rule: Zero .unwrap() in production code. All errors are propagated via Result<T, AiError>. The ? operator handles propagation, and ResultExt::context() adds human-readable context.

Deployment

Use as a Rust dependency. Compile into your application binary. Zero external services required.

Simplest

Run the HTTP server binary. OpenAI-compatible API. Docker support. TLS via rustls or reverse proxy.

Most common

Advanced

Production Checklist

  1. Enable authentication (auth.enabled = true)
  2. Set specific CORS origins (not wildcard *)
  3. Enable TLS (via server-tls feature or reverse proxy)
  4. Configure logging (RUST_LOG=info)
  5. Enable Prometheus metrics (/metrics endpoint)
  6. Set up memory persistence (auto-save or manual snapshots)
  7. Configure rate limiting
  8. Set request body size limits
  9. Add health checks (/health for Docker/K8s probes)
  10. Run as non-root user
  11. Keep secrets in environment variables, not config files
  12. Schedule regular backups of session and RAG data
