Prerequisites

ai_assistant is a Rust library. You need the Rust toolchain and at least one LLM provider.

1

Install Rust (1.82+)

If you don't have Rust installed:

bash 
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

On Windows, download rustup-init.exe from rustup.rs. Verify with: rustc --version (must be 1.82 or higher).

2

Install an LLM Provider

You need at least one local or cloud LLM provider. The easiest option:

  • Ollama (recommended) — Download from ollama.com, then: ollama pull llama3.2
  • LM Studio — Download from lmstudio.ai, start the local server
  • OpenAI / Anthropic / Gemini — Get an API key from the respective provider
Tip: Ollama is the fastest path — one install, one ollama pull command, and you're ready.

Installation

3

Add to Your Cargo Project

Add ai_assistant_core as a dependency in your Cargo.toml:

Cargo.toml 
# From git (full project — all features):
[dependencies]
ai_assistant_core = { git = "https://github.com/OrlandoLuque/ai_assistant", features = ["full"] }

# Or from crates.io (basic providers only):
# ai_assistant_core = { version = "0.1", features = ["full"] }

Or install a binary directly:

bash 
cargo install ai_assistant_core --bin ai_assistant_cli --features "full,butler"
cargo install ai_assistant_core --bin ai_assistant_server --features "full"
Important: The crates.io package contains basic LLM provider integration only. The full project (520K+ LoC — RAG, multi-agent, distributed, autonomous, security, etc.) is available from the GitHub repository.
4

Or Build the Standalone Binaries

You can also build the included server and CLI binaries directly:

bash 
# Build the HTTP server
cargo build --release --features full --bin ai_assistant_server

# Build the power-user CLI (with diagnostic logging)
cargo build --release --features "full,diagnostic-logging" --bin ai_cli

# Build the interactive CLI
cargo build --release --features full --bin ai_assistant_cli

# Binaries are in target/release/

Your First Chat

The simplest way to interact with an LLM through ai_assistant — in under 20 lines of Rust.

main.rs 
use ai_assistant::AiAssistant;

fn main() {
    // Create the assistant (auto-detects Ollama at localhost:11434)
    let mut assistant = AiAssistant::new();

    // Fetch available models from the provider
    assistant.fetch_models();

    // Wait for models to load
    loop {
        if let Some(models) = assistant.poll_models() {
            println!("Available models: {:?}", models);
            break;
        }
        std::thread::sleep(std::time::Duration::from_millis(100));
    }

    // Select a model
    assistant.select_model("llama3.2");

    // Send a message (non-streaming)
    let response = assistant.generate("What is Rust?");
    println!("Response: {}", response);
}

Streaming Responses

For real-time token-by-token output, use the streaming API:

streaming.rs 
use ai_assistant::AiAssistant;

fn main() {
    let mut assistant = AiAssistant::new();
    assistant.fetch_models();
    // ... (wait for models, select one as above)

    // Start a streaming message
    assistant.send_message("Explain async/await in Rust");

    // Poll for streaming chunks
    loop {
        match assistant.poll_response() {
            Some(ai_assistant::StreamEvent::Chunk(text)) => {
                print!("{}", text);  // Print each token as it arrives
            }
            Some(ai_assistant::StreamEvent::Complete(full)) => {
                println!("\n\n--- Complete ---");
                break;
            }
            Some(ai_assistant::StreamEvent::Error(e)) => {
                eprintln!("Error: {}", e);
                break;
            }
            None => {
                std::thread::sleep(std::time::Duration::from_millis(10));
            }
        }
    }
}

Switching Providers

ai_assistant supports 18 providers. Switch between them at runtime:

providers.rs 
use ai_assistant::{AiAssistant, ProviderType};

fn main() {
    let mut assistant = AiAssistant::new();

    // Use Ollama (local, default)
    assistant.set_provider(ProviderType::Ollama);
    assistant.set_provider_url("http://localhost:11434");

    // Or use LM Studio (local)
    assistant.set_provider(ProviderType::LmStudio);
    assistant.set_provider_url("http://localhost:1234");

    // Or use OpenAI (cloud)
    assistant.set_provider(ProviderType::OpenAi);
    assistant.set_api_key("sk-...");

    // Or use Anthropic (cloud)
    assistant.set_provider(ProviderType::Anthropic);
    assistant.set_api_key("sk-ant-...");

    // All providers share the same API:
    assistant.fetch_models();
    // ...
}

HTTP Server

ai_assistant includes an embedded HTTP server with OpenAI-compatible endpoints. Run it as a standalone service or embed it in your application.

Running the Server Binary

bash 
# Build and run with default settings (port 8090)
cargo run --release --features full --bin ai_assistant_server

# Or with a config file
cargo run --release --features full --bin ai_assistant_server -- --config config.toml

# Dry-run mode (validate config without starting)
cargo run --release --features full --bin ai_assistant_server -- --dry-run

Test It with curl

bash 
# Health check
curl http://localhost:8090/health

# Send a chat message
curl -X POST http://localhost:8090/chat \
  -H "Content-Type: application/json" \
  -d '{"message": "What is Rust?"}'

# Streaming response (SSE)
curl -X POST http://localhost:8090/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"message": "Explain ownership in Rust"}'

# List available models
curl http://localhost:8090/models

# OpenAI-compatible endpoint (works with Open WebUI, LangChain, etc.)
curl -X POST http://localhost:8090/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llama3.2",
    "messages": [{"role": "user", "content": "Hello!"}],
    "stream": false
  }'
OpenAI compatible! The /v1/chat/completions endpoint is a drop-in replacement. Point Open WebUI, LangChain, LiteLLM, Cursor, or any OpenAI-compatible tool at http://localhost:8090 and it just works.

Embedding the Server in Your App

embed_server.rs 
use ai_assistant::{AiAssistant, ServerConfig};

fn main() {
    let assistant = AiAssistant::new();
    let config = ServerConfig {
        host: "127.0.0.1".to_string(),
        port: 8090,
        auth: Default::default(),     // No auth by default
        cors: Default::default(),     // CORS with wildcard origin
        ..Default::default()
    };

    // This blocks — the server runs until killed
    assistant.run_server_blocking(&config);
}

  const { done, value } = await reader.read();
  if (done) break;

Adding RAG (Knowledge)

Give your assistant domain-specific knowledge by loading documents. ai_assistant supports PDF, EPUB, DOCX, HTML, Markdown, TXT, CSV, and more.

rag_example.rs 
use ai_assistant::AiAssistant;

fn main() {
    let mut assistant = AiAssistant::new();
    // ... (configure provider and model)

    // Register a knowledge document
    assistant.register_knowledge_document(
        "rust_guide",
        &std::fs::read_to_string("rust_guide.md").unwrap()
    );

    // Start background indexing (embeddings + vector DB)
    assistant.start_background_indexing();

    // Wait for indexing to complete
    loop {
        if let Some(progress) = assistant.poll_indexing() {
            if progress.is_complete() { break; }
        }
        std::thread::sleep(std::time::Duration::from_millis(100));
    }

    // Now chat with RAG context
    let context = assistant.build_rag_context("How do lifetimes work?");
    assistant.send_message_with_context(
        "How do lifetimes work?",
        &context
    );

    // Or use the automatic RAG pipeline
    let response = assistant.generate_with_knowledge(
        "Explain the borrow checker",
        2000  // max knowledge tokens
    );
    println!("{}", response);
}

RAG Tiers

ai_assistant implements a 5-tier RAG architecture, from simple retrieval to self-correcting:

TierStrategyDescription
T1Naive RAGSimple vector similarity search
T2Enhanced RAGReranking + hybrid search (semantic + keyword)
T3Self-RAGSelf-evaluating retrieval with relevance scoring
T4CRAGCorrective RAG — detects and fixes poor retrievals
T5Graph RAG / RAPTORKnowledge graph traversal + hierarchical summarization

Docker Deployment

Deploy the server in a container with a single command. The included Dockerfile uses multi-stage builds for a minimal ~80 MB runtime image.

bash 
# Build the Docker image
docker build -t ai-assistant:latest .

# Run with default settings
docker run -d --name ai-assistant \
  -p 8090:8090 \
  -e RUST_LOG=info \
  ai-assistant:latest

# With config file and data persistence
docker run -d --name ai-assistant \
  -p 8090:8090 \
  -v ./config:/app/config \
  -v ./data:/app/data \
  -e RUST_LOG=info \
  -e AI_CONFIG_PATH=/app/config/config.toml \
  ai-assistant:latest

Docker Compose

docker-compose.yml 
version: '3.8'
services:
  ai-assistant:
    image: ai-assistant:latest
    ports:
      - "8090:8090"
    volumes:
      - ./config:/app/config
      - ./data:/app/data
    environment:
      - RUST_LOG=info
      - AI_CONFIG_PATH=/app/config/config.toml
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-sf", "http://localhost:8090/health"]
      interval: 30s
      timeout: 5s
      retries: 3
LLM Provider access: If your Ollama or LM Studio runs on the host machine, use host.docker.internal instead of localhost in the Ollama URL config (e.g., http://host.docker.internal:11434).

CLI Usage

The included CLI binary provides an interactive terminal chat interface.

bash 
# Run the interactive CLI
cargo run --features full --bin ai_assistant_cli

# Or with a specific provider
cargo run --features full --bin ai_assistant_cli -- --provider ollama --model llama3.2

The CLI supports model selection, conversation history, session management, and all the same features as the library API.

Anti-Hallucination Verification

Use the verify subcommand to fact-check LLM answers with multiple verification strategies:

bash 
# Verify a claim using the MARK strategy with faithfulness scoring
ai_cli verify "Is Rust memory-safe without a garbage collector?" \
  --strategy mark --faithfulness

# Other strategies: consensus, cross-reference, decompose
ai_cli verify "Python is faster than C++" --strategy consensus

Academic Research Search

The research subcommand searches academic sources and exports citations (requires the research feature flag):

bash 
# Search arXiv and Google Scholar, export BibTeX
ai_cli research "transformer attention mechanisms" \
  --providers arxiv,scholar --bibtex

# Search a single provider
ai_cli research "CRISPR gene editing 2025" --providers arxiv
