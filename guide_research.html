Academic Research Guide

Search arXiv, Semantic Scholar, PubMed, OpenAlex and Crossref from a single command. Generate verified literature reviews with BibTeX export — automatically. No equivalent in LangChain or LlamaIndex.

1. Why This Matters

Academic research is one of the most time-consuming tasks in any knowledge-intensive workflow. ai_assistant eliminates the manual labour of searching, cross-referencing, and citing.

?

The Problem

  • Researchers waste hours manually searching multiple databases (arXiv, Google Scholar, PubMed) with different interfaces and query syntaxes
  • Cross-referencing results across providers requires tedious copy-paste and deduplication
  • Citation management is error-prone — wrong formats, missing fields, broken BibTeX entries
  • AI-generated literature reviews are prone to hallucination: fabricated papers, invented authors, wrong dates
!

The Solution

  • Unified search — one command, five academic databases, deduplicated by DOI
  • Automated review — structured literature reviews in four synthesis styles
  • Verified output — FaithfulnessScorer + CoVe verify every claim against source papers
  • BibTeX export — sanitized, standards-compliant citations in five bibliography formats
No equivalent in LangChain or LlamaIndex. Neither framework provides built-in academic search, literature review generation, BibTeX management, or anti-hallucination verification for research output. ai_assistant is the only framework that combines all four in a single pipeline.

2. Quick Start

Three steps to go from a research question to a cited literature review you can query.

1

Search Across Providers

Search all five providers in a single command. Results are normalised to one paper type and deduplicated by DOI.

terminal 
ai_cli research "transformer attention mechanisms" \
  --providers arxiv,scholar,pubmed,openalex,crossref \
  --max-results 30 \
  --bibtex > results.bib

--bibtex writes BibTeX to standard output, so redirect it where you want it.

2

Generate a Literature Review

Synthesize search results into a structured review with proper citations. No model is involved — the pipeline searches, groups and structures, so this runs on a machine with no local LLM and no API key.

terminal 
ai_cli research review "RLHF alignment techniques" \
  --mode systematic \
  --providers arxiv,scholar,openalex \
  --out review.md --bibtex

Two presets: --mode quick and --mode systematic, which differ in how many papers they pull, how deep they search and which synthesis style they use. Without --out the Markdown goes to standard output.

3

Index the Papers and Ask Them

Finding fifty papers and being left holding a list is half the job. --index ingests what the search just found into a RAG database; research ask queries it.

terminal 
# search and ingest in one step
ai_cli research "retrieval augmented generation" \
  --providers openalex,crossref \
  --index papers.db

# ask the index (retrieval only, still no model)
ai_cli research ask "what do they say about hallucination?" \
  --index papers.db --top-k 5

Papers are keyed by DOI, so re-running the same search re-indexes nothing and finding the same paper through two providers files it once.

3. Academic Search Providers

ai_assistant integrates five academic search APIs through a unified AcademicSearchEngine interface. Providers are queried in turn and results are deduplicated by DOI — the only identifier that survives finding the same paper through two different providers.

ProviderAPI TypeAuthRate LimitBest For
arXiv Atom/XML None 3s between requests CS, Physics, Math preprints
Semantic Scholar REST/JSON Optional API key 100 req/5min (free) CS with citation graph traversal
PubMed E-utilities XML Optional API key 3 req/s (10 with key) Biomedical & life sciences
OpenAlex REST/JSON Contact address (polite pool) 100k/day, 10/s Everything — ~250M works, all disciplines
Crossref REST/JSON Contact address (polite pool) Unmetered in the polite pool Authoritative metadata for any DOI

API Key Configuration

arXiv requires no authentication. For higher rate limits on the other providers, set environment variables:

terminal 
# Semantic Scholar — raises limit from 100/5min to 1000/5min
export SEMANTIC_SCHOLAR_API_KEY="your-key-here"

# PubMed / NCBI — raises limit from 3/s to 10/s
export NCBI_API_KEY="your-key-here"

# OpenAlex and Crossref — a contact address, not a key. It puts requests in the
# "polite pool", which is a much higher quota, not a courtesy.
export OPENALEX_MAILTO="you@example.com"
export CROSSREF_MAILTO="you@example.com"
Being throttled is reported as being throttled. A 429 or 503 is retried with exponential backoff that honours the server's Retry-After header, and if it still fails the error says rate limited — not "network error", which used to send people looking at their connection instead of at their request rate.

4. BibTeX Support

Full BibTeX parsing and generation with security sanitization. Import existing .bib files into the RAG knowledge base or export search results.

Supported Entry Types (9)

BibTeX TypeDescription
@articleJournal article
@bookBook
@inproceedingsConference or workshop paper
@incollectionChapter in a collected volume
@phdthesisPhD or Master's thesis
@techreportTechnical report
@miscMiscellaneous
@unpublishedUnpublished work
@onlineOnline resource

Import & Export

terminal 
# Export search results as BibTeX (written to stdout)
ai_cli research "diffusion models" --providers arxiv --bibtex > diffusion.bib

# Ingest the papers into a RAG index instead
ai_cli research "diffusion models" --providers arxiv --index papers.db
Importing a .bib file is available over MCP, not from the CLI. The import_bibtex tool takes a .bib and loads it into the knowledge base; BibParser is public in the Rust API. There is no ai_cli research import-bib subcommand.
Rust API 
use ai_assistant::bibtex::{BibParser, BibGenerator, BibEntry};

// Parse an existing .bib file
let content = std::fs::read_to_string("references.bib").expect("read .bib");
let entries: Vec<BibEntry> = BibParser::parse(&content)?;
println!("Parsed {} entries", entries.len());

// Generate BibTeX from search results
let generator = BibGenerator::new();
let bibtex_str = generator.generate(&entries);
std::fs::write("export.bib", bibtex_str)?;
Security: All BibTeX field values are sanitized to strip dangerous LaTeX commands: \input, \include, \write18, \immediate, \openout, \csname. This prevents LaTeX injection attacks when compiling exported .bib files.
Limits: Max file size: 10 MB. Max entries: 10,000. Max field value length: 10,000 characters. These limits are enforced during both parsing and generation to prevent resource exhaustion.

5. Literature Review Pipeline

The review pipeline takes a research question, searches across providers, filters and ranks results, synthesizes a structured review, and exports citations — all in one command.

Search Depths

DepthMax PapersStrategy
Quick20Single pass, fastest results
Standard50Multi-provider, deduplicated
Deep100Citation graph traversal, most thorough

Synthesis Styles

StyleDescriptionBest For
NarrativeFlowing prose review connecting themesThesis introductions, survey papers
SystematicStructured with tables and categorizationSLRs, meta-analyses
AnnotatedPaper-by-paper summaries with commentaryReading lists, lab meetings
ComparativeContrasting approaches side by sideMethod comparison, related work sections

Bibliography Formats (5)

Export citations in BibTeX, APA 7th, MLA 9th, Chicago 17th, or IEEE format.

Pipeline Stages

Search arXiv + Scholar + PubMed + OpenAlex + Crossref
→
Filter Deduplicate & rank
→
Synthesize LLM review generation
→
Cite BibTeX / APA / MLA / ...
→
Export .bib + .md / .tex
Rust API 
use ai_assistant::academic_search::{AcademicSearchEngine, ArxivProvider, OpenAlexProvider};
use ai_assistant::literature_review::{LiteratureReviewConfig, LiteratureReviewPipeline};

let mut engine = AcademicSearchEngine::new();
engine.add_provider(Box::new(ArxivProvider::new()));
engine.add_provider(Box::new(OpenAlexProvider::new()));

// `quick()` and `systematic()` are presets; the config fields
// (max_papers, search_depth, synthesis_style, year_range…) are public.
let config = LiteratureReviewConfig::systematic();

// Synchronous, and no model involved: the pipeline searches, groups and structures.
let review = LiteratureReviewPipeline::new(engine, config)
    .execute("reinforcement learning from human feedback");

println!("{} of {} papers, {} words",
         review.papers_included, review.papers_found, review.total_word_count());
std::fs::write("review.md", review.to_markdown())?;
std::fs::write("review.bib", &review.bibtex)?;

6. Paper Metadata Extraction

Extract structured metadata from academic paper text — title, authors, abstract, and section boundaries. Uses heuristic section detection based on common paper structures.

Detected Section Types

Section TypeDetected Headings
Abstract"abstract"
Introduction"introduction"
RelatedWork"related work", "literature review", "background", "prior work"
Methodology"method", "approach", "framework", "model", "architecture"
Results"result", "experiment", "evaluation", "finding"
Discussion"discussion"
Conclusion"conclusion", "summary", "future work"
Rust API 
use ai_assistant::paper_metadata::{PaperMetadataExtractor, SectionType};

let extractor = PaperMetadataExtractor::new();
let paper_text = std::fs::read_to_string("paper.txt")?;
let metadata = extractor.extract(&paper_text)?;

println!("Title: {}", metadata.title);
println!("Authors: {:?}", metadata.authors);
for section in &metadata.sections {
    println!("[{:?}] {} ({} chars)",
        section.section_type,
        section.heading,
        section.content.len());
}
Tip: Metadata extraction works on plain-text paper content. For PDFs, first parse with the document parsing module (document_parsing) to extract text, then pass to the metadata extractor.

7. Verified Research — Anti-Hallucination Integration

AI-generated literature reviews are prone to hallucination: fabricated papers, invented authors, wrong publication dates, and misattributed claims. ai_assistant is the only framework that verifies its own research output before returning it to the user.

Why This Is Critical for Academic Research

A fabricated citation in a literature review can invalidate an entire paper. Standard LLM frameworks generate reviews without any verification — they cannot tell you whether a cited paper actually exists or whether a claim is faithfully attributed.

  • LLMs invent plausible-sounding paper titles, author names, and DOIs
  • LLMs misattribute findings from one paper to another
  • LLMs fabricate statistics and quantitative claims
  • None of this is detectable without automated verification against source material

FaithfulnessScorer

The FaithfulnessScorer decomposes the generated review into individual claims and verifies each claim against the source papers that were actually retrieved. Every claim receives a faithfulness score from 0.0 (unsupported) to 1.0 (fully supported).

Rust API 
use ai_assistant::faithfulness::FaithfulnessScorer;

let scorer = FaithfulnessScorer::new();

// Score the review against the papers it claims to cite
let result = scorer.score(
    &review.text,        // the generated review
    &source_documents,   // the actual retrieved papers
)?;

println!("Overall faithfulness: {:.2}", result.overall_score);
for claim in &result.claims {
    println!("  [{:.2}] {}", claim.score, claim.text);
    if claim.score < 0.5 {
        println!("    WARNING: Unsupported claim!");
    }
}

Quality Gates

Quality gates enforce minimum thresholds. If the review fails a gate, it is rejected and regenerated with stricter constraints — not returned to the user in a degraded state.

Rust API 
use ai_assistant::quality_gates::QualityGate;

// Reject reviews with faithfulness below 0.7
let gate = QualityGate::faithfulness_threshold(0.7);

if !gate.passes(&faithfulness_result) {
    // Regenerate with stricter constraints
    eprintln!("Review failed quality gate (score: {:.2})",
        faithfulness_result.overall_score);
}

Chain-of-Verification (CoVe)

CoVe (chain_of_verification) cross-checks claims from the generated review against paper content. It generates verification questions, answers them independently from the source material, and flags any discrepancies.

Rust API 
use ai_assistant::chain_of_verification::CoVeVerifier;

let verifier = CoVeVerifier::new();
let verification = verifier.verify(&review.text, &source_documents)?;

for check in &verification.checks {
    println!("[{}] Q: {}", check.status, check.question);
    println!("       Expected: {}", check.expected);
    println!("       Found:    {}", check.found);
}

Review and Verification — Two Commands

Building the review and verifying claims against sources are separate commands, and deliberately so: the review needs no model, and verification does.

terminal 
# 1. Build the review — search, group, structure, cite. No model.
ai_cli research review "RLHF" --mode systematic --out review.md --bibtex

# 2. Ask a grounded question about it, with the anti-hallucination pipeline on.
ai_cli verify "Which papers evaluate on human preferences, and when?" \
  --knowledge review.md \
  --faithfulness \
  --cove \
  --quality-gates

They are not chained automatically. Nothing today takes the review's own sentences and runs each one through the verifier; you choose what to check. This page previously showed a single command that did all of it — that command never existed.

ai_assistant is the only framework that verifies its own literature review output. LangChain, LlamaIndex, Haystack, and AutoGen do not provide built-in faithfulness scoring, quality gates, or chain-of-verification for generated research output. See the Anti-Hallucination Guide for the full pipeline details.

8. Research Agent Roles

The multi-agent system includes three research-specific roles that collaborate to produce high-quality, verified academic output.

R

ResearchAssistant

Searches for academic papers, filters relevant results, summarizes findings, and provides structured literature reviews. Uses the academic search providers and BibTeX generator.

P

PeerReviewer

Critically evaluates drafts, verifies claims against sources, checks citations, and provides constructive feedback. Integrates with the FaithfulnessScorer and hallucination detection.

W

WritingCoach

Improves academic writing quality — clarity, structure, argumentation, and proper citation style. Ensures the output meets publication standards.

Multi-Agent Systematic Review Workflow

ResearchAssistant Search & gather papers
→
ResearchAssistant Draft literature review
→
PeerReviewer Verify claims & citations
→
WritingCoach Polish & finalize
Rust API 
use ai_assistant::multi_agent::{AgentRole, MultiAgentOrchestrator};

let mut orchestrator = MultiAgentOrchestrator::new();

// Define the systematic review pipeline
orchestrator.add_agent(AgentRole::ResearchAssistant);
orchestrator.add_agent(AgentRole::PeerReviewer);
orchestrator.add_agent(AgentRole::WritingCoach);

// Execute — each agent processes sequentially, passing output to the next
let result = orchestrator.execute(
    "Write a systematic review on diffusion models for image generation"
).await?;

10. Configuration

Configure the research module via TOML or programmatically. The research feature flag must be enabled (it is included in the full meta-feature).

Feature Flag

Cargo.toml 
[dependencies]
ai_assistant_core = { git = "https://github.com/OrlandoLuque/ai_assistant", features = ["research"] }

# Or enable everything:
# features = ["full"]

TOML Configuration

config.toml 
[research]
# Which providers to search when none are given on the command line.
# Available: "arxiv", "semantic_scholar", "pubmed", "openalex", "crossref"
default_providers = ["arxiv", "semantic_scholar", "pubmed"]

# Default max results per search
default_max_results = 10

# Default bibliography format: "bibtex", "apa", "mla", "chicago", "ieee"
default_bibliography_format = "bibtex"

# Optional API keys. Both fall back to the environment variables
# SEMANTIC_SCHOLAR_API_KEY and NCBI_API_KEY when unset.
semantic_scholar_api_key = ""
ncbi_api_key = ""
Rate limiting is not configured here: each provider applies its own published limit, and a 429 or 503 is retried with exponential backoff honouring Retry-After. OpenAlex and Crossref take a contact address through OPENALEX_MAILTO and CROSSREF_MAILTO.

11. Security

The research module follows the same zero-compromise security model as the rest of ai_assistant.

1

Rate Limiting

Each provider enforces its own rate limit. arXiv: 3s between requests. Semantic Scholar: 100 req/5min (free tier). PubMed: 3 req/s (10 with API key). Limits are respected automatically by AcademicSearchEngine — no manual throttling needed.

2

API Key Handling

API keys are sourced exclusively from environment variables (SEMANTIC_SCHOLAR_API_KEY, NCBI_API_KEY). They are never logged, never included in error messages, and never written to disk.

3

BibTeX Sanitization

All BibTeX field values are sanitized against LaTeX injection attacks. Dangerous commands (\input, \include, \write18, \immediate, \openout, \csname) are stripped before export.

4

File & Resource Limits

Import operations enforce strict limits: 10 MB max file size, 10,000 max entries, 10,000 max characters per field value. Query parameters are URL-encoded. Response Content-Type is validated before parsing.
