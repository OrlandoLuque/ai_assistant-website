Local Inference Runtimes — Install Guide

ai_assistant works with four first-class local runtimes — Ollama, LM Studio, llama.cpp, and vLLM. All four speak OpenAI-compatible HTTP, so the difference shows up in performance characteristics, not API surface.

1. At a Glance

Pick a runtime by workload. Single-user chat? Ollama. GPU multi-agent? vLLM. Run ai_setup recommend --workload <kind> to get the butler's pick.

Runtime Default port Model format Best for
Ollama 11434 GGUF (pulled) Single-user interactive chat
LM Studio 1234 GGUF (GUI-picked) Exploration with a GUI
llama.cpp 8080 GGUF (manual) CPU-only, exotic quantizations
vLLM 8000 HuggingFace repo GPU multi-agent / batch

Pick one with:

terminal 
ai_setup recommend --workload <kind>

Then install with:

terminal 
ai_setup install <ollama|vllm|llamacpp>

2. Ollama

The easiest local runtime. One command to install, one command to pull a model. If you don't know what you want, pick this.

Linux

terminal 
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.1:8b
ollama serve   # (most distros run this automatically via systemd)

macOS

Download the installer from ollama.com/download and run it. Creates a menubar app that manages the server.

Windows

Download the installer from ollama.com/download. Runs as a user service — no WSL required.

Point ai_assistant at Ollama

ai_config.toml 
provider = "ollama"
selected_model = "llama3.1:8b"
[urls]
ollama = "http://localhost:11434"

3. LM Studio

GUI-based model browser and server. Best if you want to browse quantizations visually or A/B models side-by-side.

Install

Install from lmstudio.ai. After picking a model in the UI, enable the Local Server tab (defaults to port 1234).

Point ai_assistant at LM Studio

ai_config.toml 
provider = "lm_studio"
selected_model = "TheBloke/Llama-3.1-8B-Instruct-GGUF"
[urls]
lm_studio = "http://localhost:1234"

4. llama.cpp

The underlying engine behind Ollama and LM Studio, but usable directly.

When to pick it

  • Quantizations that Ollama doesn't expose (e.g. Q1_0 on the PrismML fork for Bonsai models).
  • CPU-only operation on a machine without a supported GPU.
  • Tight control over -c (context), -ngl (GPU layers), -t (threads).

Linux

Pre-built CUDA binaries from llama.cpp releases, or build from source:

terminal 
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
cmake -B build -DGGML_CUDA=ON
cmake --build build --config Release -j

macOS

terminal 
brew install llama.cpp

Apple Silicon is a first-class target — Metal offload is on by default.

Windows

powershell 
winget install ggml.llamacpp

Or download a release zip and add the folder containing llama-server.exe to PATH.

Run

terminal 
llama-server -m /path/to/model.gguf --host 0.0.0.0 --port 8080

Point ai_assistant at llama.cpp

ai_config.toml 
provider = "llama_cpp"
selected_model = "my-model"
[urls]
llama_cpp = "http://localhost:8080"

Or let ai_assistant supervise llama-server for you (v0.2.52+)

The vision feature ships an opt-in process supervisor that spawns and watches a local llama-server, validates its --mmproj path, polls /health, and kills the child on Drop — so a panicking caller never leaks the process. For vision workloads, the catalog and router now prefer Qwen2.5-VL over Gemma 3 (Gemma 3 is reserved for the edge / on-device tier).

rust 
use ai_assistant::embedded_server::{LlamaServerConfig, EmbeddedLlamaServer};

let config = LlamaServerConfig::builder()
    .binary_path("/usr/local/bin/llama-server")
    .model_path("/models/Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf")
    .mmproj("/models/Qwen2.5-VL-7B-Instruct-mmproj-f16.gguf")
    .port(0)               // 0 = auto-pick a free port
    .gpu_layers(99)
    .build()?;

let mut server = EmbeddedLlamaServer::new(config);
server.start()?;
server.wait_until_ready(std::time::Duration::from_secs(60))?;
// server is killed cleanly when it goes out of scope

5. vLLM

GPU-optimised serving engine with PagedAttention and continuous batching. Typically 2–10x higher throughput than Ollama/llama.cpp under concurrent load on the same GPU.

When to pick it

  • Multi-agent orchestration (≥2 concurrent requests).
  • Eval batches over many prompts.
  • Long-running autonomous coding loops (Aider/Cline-style).
  • Research pipelines with many sequential queries per document.

Linux (native)

Prerequisites: NVIDIA GPU with CUDA 12.1+, Python 3.9–3.12.

terminal 
pip install vllm
vllm serve Qwen/Qwen2.5-7B-Instruct --host 0.0.0.0 --port 8000

Docker (recommended for Windows, optional elsewhere)

terminal 
docker run --rm --gpus all -p 8000:8000 \
  -v "$HOME/.cache/huggingface":/root/.cache/huggingface \
  --ipc=host \
  vllm/vllm-openai:latest \
  --model Qwen/Qwen2.5-7B-Instruct --port 8000

--ipc=host is required — vLLM uses NCCL shared memory.

Windows

vLLM has no native Windows build. Two options:

  1. WSL2 + Ubuntu: 
    wsl --install -d Ubuntu
# inside WSL:
pip install vllm
  2. Docker Desktop with GPU passthrough (--gpus all).

macOS

vLLM on macOS is experimental (CPU/MPS only). For Apple Silicon, llama.cpp is usually faster — stick with llama.cpp until upstream Metal support matures.

Gated repos

Some HuggingFace repos (meta-llama/*, some mistralai/*) require license acceptance + an auth token:

terminal 
export HF_TOKEN=hf_...
vllm serve meta-llama/Llama-3.1-8B-Instruct --port 8000

ai_setup recommend and the curated catalog flag which models are gated.

Point ai_assistant at vLLM

ai_config.toml 
provider = "vllm"
selected_model = "Qwen/Qwen2.5-7B-Instruct"
[urls]
vllm = "http://localhost:8000"

Tuning flags (V103.1)

Once vLLM is picked, these VLlmLaunchConfig fields cover the tuning most workloads need. All are off by default; set only what your workload requires.

Field / CLI flag When to set
enable_prefix_caching
--enable-prefix-caching		 Agentic / multi-agent / autonomous loops — reuses KV cache across turns with the same system prompt (5–30% latency win). Butler auto-suggests this for agentic workloads.
kv_cache_dtype = "fp8"
--kv-cache-dtype fp8		 VRAM tight. Halves KV-cache memory with negligible quality loss — lets the same GPU hold ~2x concurrent sequences.
speculative_model + num_speculative_tokens Latency-bound generation on a large model. Pair a big base (70B) with a tiny draft (1B) for 2–3x lower latency on easy tokens.
chat_template
--chat-template		 Escape hatch for models shipped with a broken or missing tokenizer_config.json chat template.

Runtime helpers (V103.1)

  • vllm_wait_until_ready(base_url, timeout, interval) — poll /health after launch (vLLM can take 30–120s to load weights) and then probe the full capability.
  • load_lora_adapter / unload_lora_adapter (src/vllm_lora.rs) — hot-swap LoRA adapters via /v1/load_lora_adapter. Requires launching with --enable-lora. After load, use lora_name as the model field.
  • scrape_vllm_metrics(base_url) (src/vllm_metrics.rs) — Prometheus /metrics scraper. Returns running / waiting requests, KV-cache usage, cumulative tokens. VLlmMetrics::saturated() flags waiting ≥ 4 or cache ≥ 0.9.
  • VLlmGuidedOptions + apply_guided (src/vllm_guided.rs) — inject guided_json / guided_regex / guided_choice into an OpenAI request body for structured output.
  • pick_quantization_for_vram(params_b, vram_mb) — returns Some("awq") when the fp16 model wouldn't fit, None otherwise. RuntimeInfo.gpu_vram_mb is now populated from nvidia-smi automatically.

6. Which one? — Rules of Thumb

  • Single-user, interactive: Ollama. Model management is one command.
  • GUI lover / model browser: LM Studio.
  • No GPU / exotic quants / Apple Silicon: llama.cpp.
  • GPU + multi-agent / autonomous / eval batch / research pipeline: vLLM. 2–10x throughput win under concurrent load.
When in doubt, run ai_setup recommend --workload <kind> and trust the butler.
