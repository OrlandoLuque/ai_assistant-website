Binary Catalogue

Twenty-six first-class executables shipped by ai_assistant — from a single-binary chat server to a cron-like job daemon, a virtual microphone, a distributed log aggregator, and matched CLI / GUI auditors for every self-learning subsystem. Every binary is gated behind feature flags, so you only build what you need.

Overview

This page is the authoritative inventory of every binary in the crate and is kept in lockstep with docs/BINARIES.md. Total user-facing binaries: 37 (plus an internal mock_llama_server used only by the test harness). Recent additions: the Recipes auditors (V106), the ACP auditors, the encrypted ai_backup tool (V128), the local-inference runner + auditors, and the PromptBreeder auditors (V97). V79 additionally ships the crate as a shared and static library with a C ABI — see Library Artifacts below.

Binaries declare required-features in Cargo.toml. If your build does not satisfy them, Cargo silently skips the binary — no compile error. This keeps the minimal build tiny while letting power users opt into the full catalogue.

CLI & REPL

ai_cli

Non-interactive CLI for scripting, CI/CD, and one-shot queries. Ships with thirteen subcommands including the V77 cost subcommand and three new V88 subcommands.

bash 
cargo run --bin ai_cli -- scan
cargo run --bin ai_cli -- query "What is Rust?"
cargo run --bin ai_cli --features full -- cost report --snapshot cost.json
cargo run --bin ai_cli --features full -- verify "Is Rust memory-safe?" --strategy cove --quality-gates
cargo run --bin ai_cli --features research -- research "transformer attention" --providers arxiv --bibtex
cargo run --bin ai_cli --features full -- quality gates list

Subcommands: scan, providers, models, config, butler, query, bench, test, cost, verify, research, quality, help.

New in V88:

  • verify — One-shot query with anti-hallucination pipeline (--strategy, --faithfulness, --cove, --quality-gates).
  • research — Search academic databases (requires research feature: --providers, --max-results, --bibtex, --review).
  • quality — Inspect or run quality gates (gates list, gates check).

ai_assistant_cli

Interactive terminal REPL. Good for exploring models without leaving the terminal.

Servers

ai_assistant_server

Reference HTTP + MCP server. Exposes chat, RAG, tools, and 49+ MCP tools. Requires full.

ai_assistant_standalone

A trimmed-down, single-binary service focused on HTTP. Good default for systemd-managed deployments.

ai_cluster_node

Spawns a distributed node that joins a QUIC mesh for cluster-wide RAG and agent federation. Requires full, server-cluster.

ai_proxy gateway hardened in V78

Production API gateway that sits in front of upstream providers (Ollama, OpenAI, Anthropic, …). Two feature profiles:

  • --features server-axum — router + round-robin LB + session affinity + health checks + optional Bearer auth (V77 parity).
  • --features "server-axum,security" — full gateway with guardrails.

Gateway middlewares (feature-gated by security):

  • Per-key rate limiter (sliding window, key:sha256(bearer) → sess → ip)
  • PII input/output filter via guardrail_pipeline::PiiGuard
  • Toxicity filter (input + output) via ToxicityGuard
  • Prompt-injection / attack guard via AttackGuard
  • Budget enforcement via DefaultCostMiddleware (returns 429 X-Reason: budget-exceeded)
  • LRU response cache — PII-safe: tainted responses are never stored
  • Append-only JSONL audit log with size + count rotation, symlink-safe open (O_NOFOLLOW on Unix, pre-check on Windows); API keys only logged as SHA-256 hash

Configuration via TOML file + CLI overrides:

# TOML config file (recommended)
ai_proxy --config examples/ai_proxy.toml

# Dry-run: validate and print the merged config
ai_proxy --config examples/ai_proxy.toml --dry-run

# CLI overrides still work and win over the file
ai_proxy --config ai_proxy.toml --port 9000 --disable-cache

New CLI flags (V78): --config, --audit-log, --audit-max-files, --enable-pii-redaction, --disable-cache, --cost-snapshot. --dry-run now validates the config and prints the merged middleware flag table.

Deprecated: --api-key CLI flag (still works, warns — prefer AI_PROXY_API_KEY env var, which wins over both the config file and --api-key).

Response headers: X-Request-Id on every response, X-Cache: HIT|MISS on /v1/chat/completions, X-Reason on 429 / 503.

Streaming (stream: true) and /v1/embeddings are passed through unmodified in V78 — full guardrail wiring over SSE/WebSocket is deferred to V80. See docs/IMPROVEMENTS_V78.md for the full design and the list of 13 security mitigations.

ai_jobs NEW V77

Cron-like job daemon. Loads a JSON manifest, validates cron expressions, and either lists, dry-runs, or executes the jobs on a 30-second tick.

bash 
cargo run --bin ai_jobs --features scheduler -- validate examples/jobs.json
cargo run --bin ai_jobs --features scheduler -- list      examples/jobs.json
cargo run --bin ai_jobs --features scheduler -- dry-run   examples/jobs.json --minutes 120
cargo run --bin ai_jobs --features scheduler -- run       examples/jobs.json

Two runtime modes per job:

  • delegated (default) — shells out to ai_cli or any shell command. Always available.
  • embedded — runs an in-process AiAssistant with access to RAG, tools, memory, and session state. Gated behind --features full.

The manifest is JSON (parallel schema to the core scheduler module, so no new Serde dependencies are pulled into the core crate):

json 
{
  "assistant": {
    "provider": "ollama",
    "model": "llama3",
    "system_prompt": "You are a concise reporting assistant."
  },
  "jobs": [
    {
      "id": "backup_nightly",
      "name": "Nightly backup",
      "cron": "0 3 * * *",
      "type": "shell",
      "command": "tar czf /backups/$(date +%F).tgz /data"
    },
    {
      "id": "rag_daily_brief",
      "name": "RAG-enhanced daily brief",
      "cron": "0 8 * * 1-5",
      "runtime": "embedded",
      "session_id": "daily_brief",
      "type": "agent",
      "task": "Generate today's daily brief using the team knowledge base"
    }
  ]
}
Security properties:
  • Per-job timeout_secs (default 60s) enforced via Child::kill().
  • MAX_JOBS = 1000 hard cap at load time.
  • std::panic::catch_unwind protects the daemon from job panics.
  • Unknown providers downgrade to Ollama with a warning.
  • API key env vars are referenced by name — never logged.
  • Manifest path is canonicalized and logged before use.

Testing

ai_test_harness

Multi-category test harness used by CI and by local developers to run feature-gated integration tests without having to remember every cargo test incantation. Requires full + browser (for crawl policy tests).

New V88 test categories:

  • anti-hallucination — 3 tests (pipeline correctness, strategy dispatch, output validation).
  • quality-gates — 4 tests (gate registration, threshold enforcement, report generation, CLI integration).
  • faithfulness — 2 tests (scoring accuracy, source attribution).
  • verification — 2 tests (claim extraction, evidence matching).
  • research — 4 tests (provider query, BibTeX export, result ranking, review mode). Gated behind research feature.

Self-Learning (V96, new)

V96 introduces three on-device learning subsystems — Skill Forge, Fragment Synthesis, and Feedback Loop — each persisting state as an append-only Blake3 hash-chained JSONL. Every subsystem ships a matched pair of auditor binaries: a headless CLI for CI/scripting and an egui dashboard for interactive review. All six honour the global freeze switch and verify chain integrity on demand.

ai_skills NEW V96

Read-only auditor for the Skill Forge registry. Lists skills in a directory, inspects a single .skill.json, verifies content + WASM Blake3 hashes, verifies the SkillLedger chain, or exports a skill bundle for offline review.

bash 
ai_skills list <SKILLS_DIR>
ai_skills inspect <SKILL.skill.json>
ai_skills ledger-verify <LEDGER_JSONL>
ai_skills export <SKILL.skill.json> <OUT_DIR>

ai_skills_gui NEW V96

Desktop companion to ai_skills. Browses a directory of skills, shows metadata, live-verifies hashes, and renders the ledger chain with colour-coded integrity status.

ai_prompt_synth NEW V96

Read-only auditor for the FragmentLedger produced by FragmentBandit (ε-random + UCB, partitioned by (provider, model) fingerprint and intent cluster).

bash 
ai_prompt_synth ledger-show    <LEDGER_JSONL> [--last N]
ai_prompt_synth ledger-verify  <LEDGER_JSONL>
ai_prompt_synth arms-summary   <LEDGER_JSONL>

ai_prompt_synth_gui NEW V96

Dashboard that replays a fragment ledger into per-cluster + per-arm views: selection counts, mean reward, retirement status, and per-arm reward-history sparklines.

ai_feedback NEW V96

Read-only auditor for the FeedbackDispatcher DispatchLedger and RetractionLedger. Aggregates per-sink dispatch / failure counts and drop-reason stats (including the InsufficientSources reward-hacking gate), and lists the full GDPR-style retraction trail.

bash 
ai_feedback ledger-show     <DISPATCH_JSONL> [--last N]
ai_feedback ledger-verify   <DISPATCH_JSONL>
ai_feedback retractions     <RETRACTION_JSONL>
ai_feedback stats           <DISPATCH_JSONL>

ai_feedback_gui NEW V96

Five-tab dashboard for the Feedback Loop: Overview (totals + chain status), Sinks, Drops, Retractions, Events (most recent 500 raw events).

ai_breeder NEW V97

Read-only auditor for the PromptBreeder V97 subsystem. Reads atomic *.ckpt snapshots and Blake3 hash-chained ledger JSONL files. Summarises populations (fitness min/mean/max, operator provenance, lineage depth) and verifies chain integrity end-to-end.

bash 
ai_breeder list-runs         <DIR>
ai_breeder show-run          <CKPT_FILE>
ai_breeder ledger-verify     <LEDGER_JSONL>
ai_breeder ledger-show       <LEDGER_JSONL> [--last N]
ai_breeder export-population <CKPT_FILE> <OUT_JSON>
ai_breeder compare-runs      <CKPT_A> <CKPT_B>

ai_breeder_gui NEW V97

Six-tab dashboard: Overview (config hash, ledger tip, fitness summary), Population (per-unit table with operator, fitness, parents, task-prompt preview), Lineage (DAG sizing + operator histogram), Ledger (chain integrity), Events (most recent 500 raw events), Fitness (best-per-generation + diversity timeline extracted from the ledger).

Shared contract across all auditable subsystems:
  • Append-only JSONL with Blake3 prev_hash → this_hash chain.
  • Optional Ed25519 signatures via the DispatchSigner trait (default: NoopDispatchSigner).
  • Global freeze switch honoured by every learner (set_frozen(true) short-circuits ingestion).
  • Each subsystem has its own event enum, but the ledger record layout is uniform — so one mental model audits all three.

Library Artifacts (V79, new)

Beyond the binaries, V79 ships ai_assistant itself as a shared and static library via the new ffi Cargo feature. Downstream C / C++ / C# / Unity / Unreal / Bevy consumers can link directly against these outputs without cargo or Rust tooling.

Platform cdylib staticlib Import lib
Linuxlibai_assistant.solibai_assistant.a—
macOSlibai_assistant.dyliblibai_assistant.a—
Windows MSVCai_assistant.dllai_assistant.libai_assistant.dll.lib
Windows GNUai_assistant.dlllibai_assistant.alibai_assistant.dll.a

Build recipe:

bash
cargo build --features ffi --profile release-fast
The profile release-fast is recommended because the default release profile uses panic = "abort", which turns the FFI's catch_unwind panic boundary into a no-op. build.rs emits a cargo:warning if it detects the dangerous combo.

The committed include/ai_assistant.h header (auto-regenerated by build.rs via cbindgen) declares:

  • 20 extern "C" functions (ai_assistant_new, ai_assistant_send_message, …)
  • 9 return-code extern const int statics (AI_OK, AI_ERR_NULL_PTR, …)
  • Flat AiProviderKind C enum (17 variants)
  • Opaque struct AiAssistantHandle

Full API reference: see docs/FFI.md in the repository. Minimal C example: examples/ffi_c/.

Required features. ffi (minimum). Add rag to dispatch send_message through generate_sync_with_rag. Add full to enable every provider/tool/middleware the Rust side knows about.
