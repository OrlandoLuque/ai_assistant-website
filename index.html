Code Snippets

Use the library directly from Rust, or connect to the server from any language.

Rust — Using the Library

use ai_assistant::{AiAssistant, AiConfig, AiProvider};

let config = AiConfig {
    provider: AiProvider::Ollama,
    selected_model: "llama3.2:1b".to_string(),
    ollama_url: "http://localhost:11434".to_string(),
    ..Default::default()
};

let mut assistant = AiAssistant::new();
assistant.load_config(config);
assistant.set_system_prompt("You are a helpful assistant.");
assistant.fetch_models();
assistant.send_message_simple("What is Rust?".to_string());

for msg in &assistant.conversation {
    println!("[{}] {}", msg.role, msg.content);
}

Python — Using the Server

import requests

BASE = "http://localhost:8090"

# Simple chat with system prompt
r = requests.post(f"{BASE}/chat", json={
    "messages": [
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user", "content": "What is Rust?"},
    ],
    "temperature": 0.3,
})
print(r.json()["response"])

# Or use the OpenAI SDK — our server is a drop-in replacement!
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8090/v1", api_key="not-needed")

response = client.chat.completions.create(
    model="llama3.2:1b",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(response.choices[0].message.content)

Node.js — Using the Server

const r = await fetch("http://localhost:8090/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    messages: [
      { role: "system", content: "Reply in one sentence." },
      { role: "user", content: "What is WebAssembly?" },
    ],
    temperature: 0.5,
  }),
});
const data = await r.json();
console.log(data.response);

curl

curl -X POST http://localhost:8090/chat \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "Hello!"}]}'

# OpenAI-compatible endpoint (works with Continue.dev, Cursor, LangChain...)
curl -X POST http://localhost:8090/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "llama3.2:1b", "messages": [{"role": "user", "content": "Hi!"}]}'

Built for Real-World Use Cases

From a personal assistant on a Raspberry Pi to a multi-node enterprise cluster, the same crate covers every deployment scenario.

Personal AI Assistant

Run a fully private assistant on your own hardware. Connect to Ollama or LM Studio, keep all data local, pay zero cloud costs.

  • Local LLM via Ollama / LM Studio
  • Conversational memory with persistence
  • FreshContext: auto-generated session summaries for LLM continuity
  • Document ingestion (PDF, DOCX, HTML, code)
  • MCP knowledge tools for structured context injection
  • Zero telemetry, zero network calls

Enterprise RAG Platform

Production-grade Retrieval-Augmented Generation with 5-tier adaptive routing, 7 vector DB backends, and built-in guardrails.

  • Self-RAG, CRAG, Graph RAG, RAPTOR
  • PII detection, toxicity filtering, RBAC
  • Multi-provider fallback (OpenAI, Anthropic, Gemini, Bedrock)
  • Audit logging, OpenTelemetry traces

Distributed AI Cluster

Horizontal scaling without Redis, Kafka, or Kubernetes. Built-in CRDTs, Kademlia DHT, MapReduce, and QUIC/TLS 1.3 transport.

  • Conflict-free replicated data types (CRDTs)
  • P2P discovery, anti-entropy sync
  • Distributed task execution
  • No external infrastructure required

AI-Powered Application Backend

Drop-in OpenAI-compatible HTTP server with SSE streaming, authentication, rate limiting, and gzip compression out of the box.

  • REST API with /api/v1/ versioning
  • SSE streaming (POST /chat/stream)
  • WebSocket chat endpoint (/ws)
  • TLS, CORS, Prometheus /metrics

Research & Evaluation

Built-in benchmark suites, multi-model comparison, ablation studies, and trajectory analysis for systematic AI research.

  • Eval suite with configurable benchmarks

Three Ways to Deploy

Same crate, different feature flags. Pick the deployment model that fits your needs.

Tier 1

Embedded Library

Add ai_assistant_core as a dependency in your Cargo.toml. Use only the features you need.

  • Selective feature flags (pay only for what you use)
  • Direct Rust API integration
  • Compile-time dead code elimination
  • Ideal for Rust applications, CLI tools, desktop apps
  • Embeddable in egui, Tauri, or any Rust binary
Tier 2 — Most Common

Standalone Server

Build the included HTTP server binary. Get a full REST + WebSocket API with a single cargo build.

  • OpenAI-compatible chat API
  • SSE streaming, gzip compression
  • Auth middleware, RBAC, rate limiting
  • TLS (rustls), CORS, Prometheus metrics
  • Graceful shutdown, request correlation IDs
  • Dockerfile included
Tier 3

Distributed Cluster

Enable distributed-network and p2p features. Nodes discover each other and sync automatically.

  • QUIC/TLS 1.3 transport (Quinn)
  • Kademlia DHT for peer discovery
  • CRDTs for conflict-free replication
  • Anti-entropy Merkle sync
  • Reputation tracking, join tokens
  • No Redis, no Kafka, no ZooKeeper

Security at Every Layer

Not bolted on as an afterthought. Security is woven into the architecture from input validation to encrypted persistence.

Constitutional AI Guardrails

Configurable input/output guardrail pipeline with streaming support. Block, warn, or redact.

PII Detection

Real-time detection of emails, phones, SSNs, credit cards, and custom patterns. Auto-redaction on output.

RBAC Access Control

Role-based access with MFA, CIDR IP ranges, usage limits, and time-based policies.

AES-256-GCM Encryption

Content encryption at rest with authenticated encryption. Key management built in.

mTLS & QUIC

Mutual TLS for node-to-node communication. QUIC transport with TLS 1.3 for distributed clusters.

Red Teaming

Built-in adversarial testing suite. Probe your deployment for prompt injection, jailbreaks, and data leakage.

2-pass comprehensive audit. 32 vulnerabilities identified and fixed across all modules.
